# Zweisprachige Oberfläche (DE/EN) – #94

Lars, 07.10.2026: „Das muss alles auch auf Englisch sein, nicht nur Deutsch.“

## Entscheidungen

- **Englisch ist Quellsprache und Rückfall**, Deutsch die erste Übersetzung. Wie im cable-planner (E-28 dort: englische Quelle, deutsches Wörterbuch, `npm run lang:check`). Grund: Fachbegriffe der Scopes sind englisch, Hersteller-Dokumentation ebenso; eine fehlende Übersetzung zeigt so nie einen leeren Knopf.
- **Keine Bibliothek.** `src/i18n/index.ts` hat `t(key, params)` mit `{platzhalter}` und Plural über `Intl.PluralRules` (Formen `one`/`other`, optional `zero`). Für zwei Sprachen und einige hundert Texte reicht das; i18next o. ä. brächte nur Gewicht.
- **Typsichere Schlüssel.** Je Bereich `src/i18n/en/<bereich>.ts` (Quelle, `as const satisfies Messages`) und `src/i18n/de/<bereich>.ts` (`satisfies Translation<typeof en>`). `en.ts`/`de.ts` fassen die Bereiche zusammen; `Key = keyof typeof en`. Fehlender, überzähliger oder falsch geformter Schlüssel → `tsc` rot. Der Vitest-Test prüft zusätzlich gleiche Platzhalter und Plural-Form.
  - Abweichung vom cable-planner: dort steht die englische Quelle inline als Fallback (`t('key', 'English')`). Hier verlangt der Auftrag `de.ts` und `en.ts` mit typsicheren Schlüsseln; der Rückfall ist trotzdem Englisch.
  - Eine Datei je Bereich, damit parallele PRs nicht dieselbe Datei anfassen.
- **Sprache:** gespeicherte Wahl (`lz-scopes.lang`), sonst Electron `app.getLocale()` (über preload `lzsDesktop.locale`), sonst `navigator.languages[0]`. Alles, was mit `de` beginnt → Deutsch, sonst Englisch.
- **Umschalten mit sauberem Reload.** Die Oberfläche baut viele Texte einmal beim Start (Kopfleiste, Quellenkarten, Scope-Listen, Einstellungsseiten). Ein Live-Umschalten hieße, jedes Modul neu rendern zu lassen; der Reload ist robust, Zustand (Quellen, Layout, Panels) speichert `main.ts` ohnehin. Eine laufende Kamera- bzw. Bildschirmaufnahme muss danach neu gestartet werden; der Hinweis steht in den Einstellungen. Die Einstellungen öffnen sich nach dem Reload wieder auf „Oberfläche“.
- **Tests:** `LZS_LANG` setzt in Electron den Schalter `--lang`; `launchApp()` startet standardmäßig deutsch (die bestehenden E2E-Tests prüfen deutsche Beschriftungen, die CI läuft unter `en-US`), `launchApp({ lang: 'en' })` englisch.
- **Wächter** `scripts/lang-check.mjs` (`npm run lang:check`, auch im Vitest-Test): liest Zeichenketten und Template-Texte in `src/`, `server/`, `electron/`, `companion/src/` ohne Kommentare und meldet Umlaute bzw. nur-deutsche Wörter außerhalb von `src/i18n`. Wörter, die es auch im Englischen gibt (`in`, `so`, `man`, `was`, `also`), stehen bewusst nicht auf der Liste (Lehre aus dem cable-planner). Ausnahme: `// lang-ok: <Grund>` in oder über der Zeile. Erst Warnung, seit Abschluss der Migration scharf: `STRICT` in `test/i18n.test.ts` und `npm run lang:check -- --strict` in der CI.
